# Протокол звірки стану репозиторію

> Причина існування: головна практична проблема — агент втрачає синхронізацію з фактичним станом
> репозиторію і повторно проходить уже завершені етапи. Цей протокол виконується **на початку кожної сесії**.

## Кроки

1. **Прочитати `STATE.md`** — які фази позначені DONE / IN PROGRESS / NOT STARTED.
2. **Перерахувати фактичний вміст:** дерево файлів, наявність пакетів, наявність тестів.
3. **Звірити три джерела:**
   - що написано в `STATE.md`
   - що є у файловій системі
   - що записано в `governance/ACTION_JOURNAL.md` як останній крок
4. **Класифікувати результат:**

| Результат | Дія |
|---|---|
| Три джерела збігаються | Продовжувати роботу |
| `STATE.md` каже DONE, файлів немає | **СТОП.** Доповісти. Не реалізовувати наново без вказівки |
| Файли є, `STATE.md` каже NOT STARTED | **СТОП.** Доповісти. Ймовірно робота була, але не зафіксована |
| Журнал обривається на півкроці | Доповісти про незавершений крок, запропонувати добити або відкотити |

5. **Вивести короткий звіт** у форматі:
```
ЗВІРКА
Фаза за STATE.md: 0 / NOT STARTED
Фактично: docs/ є, packages/ порожні, тестів немає
Розбіжності: немає
Готовий до: ADR-0001 (очікує «Погоджено»)
```

## Правило
Звірка — це **тільки читання**. Протокол не дозволяє нічого виправляти.
