# ADR-0003: Детермінізм симуляції та EventLog

- **Статус:** Accepted
- **Дата:** 2026-09-13
- **Погоджено:** 2026-09-14
- **Клас зміни:** A

## Контекст
Потрібні: відтворюваність для дебагу, перегляд бою, миттєва симуляція і повільна візуалізація з одного коду,
захист від непомітного дрейфу балансу при роботі ШІ-агентів.

## Рішення
- Сигнатура: `simulateFight(a, b, context, rng) → { result, eventLog }`.
- `rng` — seeded PRNG (mulberry32 або xoshiro128**), створюється з `hash(saveSeed, fightId)` і передається явно.
- `Math.random()` заборонений у пакетах рушіїв (лінт-правило).
- `EventLog` — масив подій із таймкодом раунду і секунди. Це **єдине** джерело для відображення бою.
- Візуалізація = програвання логу. Миттєвий результат = той самий лог без програвання.

## Наслідки
- Перегляд, повтор, «відео суперника» для скаутингу і шеринг боїв доступні без додаткової роботи.
- Формат `EventLog` стає публічним контрактом — його зміна потребує нового ADR.

## Доповнення при погодженні (2026-09-14)
- Словник градацій влучання і подій — **ADR-0012**.
- Сигнатура приймає план бою — **ADR-0014**.
- Ідентифікатори сутностей у логах — **ADR-0013**, ніколи не позиції.
- Разом із `Math.random()` заборонено `crypto.randomUUID()`, `Date.now()` і `new Date()`
  у пакетах рушіїв: усі три недетерміновані.

## Перевірка
Тест: 1000 боїв із фіксованими seed дають байт-ідентичні логи між запусками і між Node/браузером.
