# ADR-0001: Мова і стек

- **Статус:** Accepted
- **Дата:** 2026-09-13
- **Погоджено:** 2026-09-13
- **Клас зміни:** A

## Контекст
Цільові платформи — web, Android, iOS. Гра однокористувацька і офлайнова в перших фазах.
Ядро симуляції має запускатися і в Node (масові прогони для калібрування), і в браузері.

## Варіанти
1. **TypeScript скрізь (web-first, мобілки через Capacitor)** — один код для ядра і UI; масові прогони в Node; швидка ітерація; слабше з продуктивністю на дуже великих світах.
2. **C# + Unity** — шлях FM26; сильна графіка, але надлишкова для менеджерської гри; повільніша ітерація; ядро важче тестувати в CLI.
3. **Rust-ядро + TS-обгортка** — найшвидше, детермінізм із коробки; істотно дорожча розробка і складніша для вайб-кодінгу.

## Рішення
Варіант 1: TypeScript, web-first, мобільні збірки через Capacitor. Бекенд на Node — лише з фази 4.

## Наслідки
- Світ треба тримати в межах ~20 тис. осіб (для боксу цього з запасом достатньо — база FM на два порядки більша через інший вид спорту).
- Потрібен строгий лінт проти `Math.random()` і побічних ефектів у ядрі.
- Заміна UI у майбутньому не зачіпає ядро.

## Перевірка
Пакети рушіїв збираються і проходять тести без DOM-середовища.
