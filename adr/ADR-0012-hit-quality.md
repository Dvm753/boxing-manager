# ADR-0012: Градації влучання у FightEvent

- **Статус:** Accepted
- **Дата:** 2026-09-14
- **Погоджено:** 2026-09-14
- **Клас зміни:** A
- **Доповнює:** ADR-0003

## Контекст
`FIGHT_ENGINE_SPEC` описував влучання бінарно: `p_land`, далі шкода. Бінарний результат збіднює
`EventLog` настільки, що 2D-перегляд і статистика в стилі CompuBox не матимуть із чого будуватися,
а коментар звучатиме однаково на кожному ударі.

`EventLog` — публічний контракт (ADR-0003). Змінювати його після написання рушія дорого,
тому словник подій фіксується до першого рядка `engine-fight`.

## Рішення
Результат кожної спроби удару — одне зі значень:

```
miss → block → partial → glancing → clean → heavy → critical
```

| Значення | Що це |
|---|---|
| `miss` | не дійшов |
| `block` | прийнято на блок або парировано |
| `partial` | частково пройшов крізь захист |
| `glancing` | ковзне влучання |
| `clean` | чисте влучання |
| `heavy` | важке влучання, помітна шкода |
| `critical` | пробиває — кандидат на нокдаун або оглушення |

Окремо від градації влучання фіксуються **наслідки**: `cut` (розсічення з локацією),
`swelling`, `stun`, `balanceLoss`, `knockdown`.

У статистиці бою «влучанням» вважаються `partial` і вище; `block` не є влучанням,
але потрапляє в лог — без нього неможливо показати роботу захисту.

## Наслідки
- `FightEvent` фіксується як контракт; розширення словника = новий ADR.
- Шкода рахується від градації, а не від окремого кидка: одна випадкова величина замість двох.
- Статистика CompuBox-типу (кинуто / влучено, джеб / силові) виводиться з логу без додаткових полів.

## Перевірка
Тест схеми логу: кожна подія удару має градацію з переліку; сума `partial+` дорівнює «влучено»
у підсумковій статистиці бою.
