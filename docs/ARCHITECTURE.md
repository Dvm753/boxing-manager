# Архітектура

Похідний документ від `docs/analysis/FM_ANALYSIS.md`. Тут — тільки рішення для цього проєкту.

## Три інваріанти

Порушення будь-якого з них — дефект архітектури, а не компроміс.

1. **Симуляція — джерело правди.** UI лише читає стан і надсилає команди. UI не вирішує, хто
   переміг, не змінює рейтинг, розвиток чи контракти. Це робить виключно рушій.
2. **Бій детермінований від стану і seed.** Ті самі бійці, той самий план, той самий seed —
   завжди той самий результат (ADR-0003).
3. **Презентація ≠ симуляція.** Миттєвий результат, текстовий коментар, 2D-перегляд і колись 3D —
   це різні відображення **одного й того самого** `EventLog`. Жодне з них не має власної логіки
   бою і не може дати іншого результату, ніж інше.

## Шари

```
apps/web            UI — замінний повністю, без правил домену
  ↓
session             команди гравця, збереження, undo
  ↓
engine-world        тік дня, економіка, рейтинги, прогресія
  ↓
ai                  політики рішень промоутерів, менеджерів, бійців
  ↓
engine-fight        симуляція одного бою (чиста детермінована функція)
  ↓
data                JSON-довідники, генератор світу
  ↓
core-model          сутності, типи, схеми
```

Залежності односторонні. Зворотний імпорт — дефект збірки.

## Принципи (успадковані з аналізу FM)

1. **Симетрія ШІ і гравця.** ШІ-менеджери й промоутери користуються тим самим API дій, що й гравець. Без цього світ мертвий.
2. **Ядро окремо від обличчя.** UI можна викинути й переписати, не торкаючись симуляції. FM26 підтвердив ціну порушення цього принципу зворотним боком: рушій похвалили, інтерфейс — ні.
3. **Дані не в коді.** Ваги, органи, стилі, коефіцієнти — JSON.
4. **Прихована інформація як механіка.** Реальні атрибути приховані; гравець бачить оцінку з похибкою, яку звужує скаутингом і переглядом боїв.
5. **Час — атомарний цикл.** Уся гра це `advanceDay()`.
6. **Детермінізм.** Один seed → один результат. Це і фіча (повтори), і запобіжник (тести).

## Ключова відмінність від FM

У FM календар заданий і матчі неминучі. У боксі календаря немає — **бій виникає з переговорів**.
Тому центральна петля гри інша:

```
стан світу → пропозиції боїв (від ШІ і від гравця)
          → переговори (гаманець, дата, ваги, раунди, реванш-клауза)
          → підписання → табір (8–12 тижнів рішень)
          → зважування → бій → наслідки (рейтинг, гроші, знос, репутація)
```

## Темп

2–4 бої на рік. Щільність рішень має йти з табору, матчмейкінгу і політики поясів, інакше між боями порожньо. Це головний ризик дизайну, а не технічний.
